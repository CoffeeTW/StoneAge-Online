# StoneAge Online v0.1-19

## Multi-participant Party Battle

This version introduces a dedicated `PartyBattleSession` rather than rewriting the existing solo/Pet battle runtime.

### Protocol

- `0x0810 PartyBattleStart`
- `0x0811 PartyBattleActionRequest`
- `0x0812 PartyBattleActionResponse`
- `0x0813 PartyBattleTurnResult`
- `0x0814 PartyBattleEnd`

### Runtime

- leader movement is the only party encounter trigger
- online same-map party members are collected by the server
- all participating client sessions enter `InBattle`
- every living participant submits exactly one action per turn
- supported actions in this version:
  - `1 Attack`
  - `2 Defend`
- the server waits until every living participant submits an action
- players and monster are then ordered by agility with a random tie breaker
- each player has independent HP
- the monster has one shared HP pool
- monster targets a random living participant
- Defend halves monster damage against that participant

### End rules

- Victory EXP is split evenly across all participants
- existing player level progression is applied independently per participant
- KO players persist with HP=1
- party battle currently has no pet actors, capture, or item drop
- disconnecting any participant aborts the whole party battle and returns remaining online participants to `InWorld`

### Compatibility

The existing solo/Pet battle opcodes and battle resolution remain unchanged. Party battle uses its own runtime and protocol so this version does not regress capture, pet skills, drops, or solo battle behavior.

For the current TestClient, existing `attack` and `defend` commands are automatically routed by the server to the active Party battle. The async receiver includes dedicated readable output for PartyBattleStart, PartyBattleActionResponse, PartyBattleTurnResult, and PartyBattleEnd.
