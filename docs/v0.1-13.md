# StoneAge Online v0.1-13

## Pet skill management

New protocol:

- `0x0909 PetSkillListRequest`
- `0x090A PetSkillListResponse`
- `0x090B PetSkillLearnRequest`
- `0x090C PetSkillLearnResponse`
- `0x090D PetSkillForgetRequest`
- `0x090E PetSkillForgetResponse`

Rules:

- pet must belong to the selected character
- management is available only while `InWorld`
- four skill slots per pet: `0..3`
- an occupied slot must be forgotten before learning a replacement
- the same pet cannot learn the same skill twice
- skill ids must exist in the server-side `PetSkillCatalog`

## Network send hardening foundation

`ConnectionSendGate` provides one shared `SemaphoreSlim` per `NetworkStream` through a `ConditionalWeakTable`.

The following paths use the shared gate in this version:

- initial Hello packet
- Ping/Pong
- world registry broadcasts
- pet skill responses

This removes the previous separate world-only lock implementation and establishes one common lock source.

### Remaining migration

Older packet handlers still contain direct `NetworkStream.WriteAsync` calls. They must be migrated to `ConnectionSendGate` before the outbound stream can be considered fully serialized. This version intentionally documents that limitation instead of claiming the transport race is fully resolved.

## CI baseline

The project uses Ubuntu 24.04 and .NET 10 GitHub Actions. CI runs on pull requests and on pushes to `main`, avoiding duplicate develop-branch push and PR runs.
