# StoneAge Online v0.1-13

## Pet skill management

New protocol:

- `0x0909 PetSkillListRequest`
- `0x090A PetSkillListResponse`
- `0x090B PetSkillLearnRequest`
- `0x090C PetSkillLearnResponse`
- `0x090D PetSkillForgetRequest`
- `0x090E PetSkillForgetResponse`

Rules:

- pet must belong to the selected character
- management is available only while `InWorld`
- four skill slots per pet: `0..3`
- an occupied slot must be forgotten before learning a replacement
- the same pet cannot learn the same skill twice
- skill ids must exist in the server-side `PetSkillCatalog`

TestClient commands:

- `petskills <petId>`
- `petlearn <petId> <skillId> <slot>`
- `petforget <petId> <slot>`

## Battle pet skill selection

New protocol:

- `0x0805 BattlePetSkillSelectRequest`
- `0x0806 BattlePetSkillSelectResponse`

The request payload is one byte containing skill slot `0..3`.

Server validation requires:

- session state is `InBattle`
- an active battle pet exists and is not KO
- slot is within `0..3`
- the selected slot belongs to the active pet
- the referenced skill exists in `PetSkillCatalog`

A successful selection updates `BattleSession.SelectedPetSkillId`. The selected skill is used for subsequent pet actions and can change the pet attack power and elemental profile.

TestClient command:

- `petskill <slot>`

## Network send hardening

`ConnectionSendGate` provides one shared `SemaphoreSlim` per `NetworkStream` through a `ConditionalWeakTable`.

All server outbound packet paths now use the shared gate, including:

- initial Hello
- Ping/Pong
- Login responses
- Character responses
- EnterWorld and world presence/movement broadcasts
- NPC responses and warp presence packets
- Inventory and Shop responses
- Item and Equipment responses
- BattleStart / BattleTurnResult / BattleEnd
- Pet management responses
- Pet skill management responses
- Battle pet skill selection responses

This removes the previous world-only locking split and prevents independent response/broadcast writers from concurrently writing bytes to the same TCP stream.

A future refactor can wrap the stream/session/gate behind a dedicated `ClientConnection` type, but outbound serialization no longer depends on separate handler-specific locks.
