# StoneAge Online v0.1-21

## Inventory Multi-Stack

`character_items` now supports multiple rows with the same `(CharacterId, ItemId)`.

### Database indexes

- `(CharacterId, ItemId)` is a normal lookup index
- `(CharacterId, Slot)` remains unique
- `(CharacterId, EquippedSlot)` remains unique when equipped

On startup, `DatabaseSchemaUpgrade` performs:

```sql
DROP INDEX IF EXISTS "IX_character_items_CharacterId_ItemId";
CREATE INDEX IF NOT EXISTS "IX_character_items_CharacterId_ItemId"
    ON character_items ("CharacterId", "ItemId");
```

This upgrades an existing database without deleting inventory rows.

## Shared Stack Rules

`InventoryStackService` is the common inventory mutation rule used by shop and battle reward paths.

### Add

1. validate total capacity before changing rows
2. fill existing partial stacks in slot order
3. allocate new free slots only for the remaining quantity
4. never create a stack above `MaxStack`
5. if total capacity is insufficient, make no inventory mutation

Example with `MaxStack = 99`:

- existing: `80`
- add: `150`
- result: `99 + 99 + 32`

provided enough inventory slots are free.

### Remove for sale

1. only unequipped stacks are eligible
2. validate aggregate unequipped quantity before changing rows
3. consume stacks in slot order
4. delete rows that reach zero
5. if aggregate eligible quantity is insufficient, make no inventory mutation

## Shop

- Buy can span multiple stacks
- Buy fills partial stacks before opening new slots
- Sell can consume quantity from multiple stacks
- equipped rows are excluded from sellable quantity
- Stone and inventory changes remain in one database transaction

## Battle Drops

Both solo and party battle drops use the same multi-stack add rule.

A drop now:

- fills an existing partial stack when possible
- creates a new stack when the previous stack is full and a slot is available
- fails only when the item is unknown or total inventory capacity is insufficient

The v0.1-20 workaround that skipped a party drop merely because the existing stack was full is no longer needed.

## Compatibility

- Item Use operates by `CharacterItem.Id`, so duplicate ItemId stacks are unambiguous
- Equip operates by `CharacterItem.Id`
- Unequip operates by unique equipped slot
- Inventory list already exposes every row and slot separately
- no packet format change is required for v0.1-21
