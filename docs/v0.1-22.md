# StoneAge Online v0.1-22

## EF migration bridge

This version introduces a non-destructive bridge from the legacy startup schema upgrader to EF Core migrations.

Startup order in v0.1-22:

1. `EnsureCreatedAsync()` keeps fresh installations working during the transition.
2. `DatabaseSchemaUpgrade.ApplyAsync()` aligns databases created by older versions to the v0.1-21 schema.
3. `MigrationBootstrap` creates `__EFMigrationsHistory` when needed.
4. The no-op baseline migration `20260826000000_LegacyV0121Baseline` is recorded.
5. `Database.MigrateAsync()` applies any migrations newer than the baseline.

The baseline migration never creates or drops gameplay tables. Existing accounts, characters, inventory, pets, and pet skills are preserved.

`GameDbContextModelSnapshot` reuses `GameDbContext.ConfigureModel(...)`, keeping the baseline snapshot and runtime model configuration in one place. `Microsoft.EntityFrameworkCore.Design` is included as a private development dependency for future `dotnet ef` commands.

This is intentionally a transition release. `EnsureCreatedAsync()` and `DatabaseSchemaUpgrade` remain in the bootstrap path for legacy installations. After the migration path has been exercised by real schema deltas, a later version can remove the legacy bootstrap and use migrations exclusively.

## Automated tests

New project:

- `tests/StoneAge.Game.Tests`

Inventory tests cover:

- filling partial stacks before opening new slots
- atomic failure when inventory capacity is insufficient
- selling/removing across multiple unequipped stacks
- excluding equipped stacks from removable quantity
- atomic failure when removable quantity is insufficient

Party battle tests cover:

- waiting for every living participant before turn resolution
- rejecting duplicate submissions in the same turn
- excluding knocked-out participants from the action barrier

GitHub Actions now restores the test project and executes `dotnet test` after Server and TestClient builds.
