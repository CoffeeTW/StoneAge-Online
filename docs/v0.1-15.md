# StoneAge Online v0.1-15

## ClientConnection migration

The transport boundary continues the v0.1-14 migration. These handlers now directly implement:

```csharp
Task HandleAsync(ClientConnection connection, PacketFrame packet, CancellationToken ct)
```

Migrated in the current batch:

- LoginPacketHandler
- CharacterPacketHandler
- NpcPacketHandler
- PetPacketHandler
- PetSkillPacketHandler
- WorldPacketHandler (already migrated in v0.1-14)

Migrated handlers send through `connection.SendAsync(...)` rather than accepting a raw `NetworkStream`.

During the mixed migration period `IClientPacketHandler` provides a temporary two-way compatibility bridge. Legacy wrappers are non-owning and never dispose the real TCP transport. The bridge must be removed after the remaining Inventory / Equipment / Battle handlers are migrated.

## Pet recovery

New protocol:

- `0x090F PetHealRequest`
- `0x0910 PetHealResponse`
- `0x0911 PetReviveRequest`
- `0x0912 PetReviveResponse`

Both requests carry one `Int64 PetId`.

Rules are server-authoritative:

- session must be `InWorld`
- pet must belong to the selected character
- Heal requires `0 < HP < MaxHP`
- Heal restores HP to MaxHP
- KO pets cannot be healed and must be revived first
- Revive requires `HP == 0`
- Revive restores `max(1, MaxHP / 2)`
- HP changes are persisted immediately to PostgreSQL

This is an initial recovery primitive. A later version can attach costs to recovery through consumable items, Stone, or a healer NPC without changing the ownership/HP validation rules.
