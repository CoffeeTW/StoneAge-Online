# StoneAge Online v0.1-15

## ClientConnection migration complete

All gameplay packet handlers now directly implement:

```csharp
Task HandleAsync(ClientConnection connection, PacketFrame packet, CancellationToken ct)
```

The temporary `(GameSession, PacketFrame, NetworkStream, CancellationToken)` compatibility bridge has been removed from `IClientPacketHandler` and `CompositePacketHandler`.

`ClientConnection` can now only be created from a real `TcpClient`; the temporary non-owning legacy wrapper constructor has also been removed.

Migrated handlers:

- WorldPacketHandler
- LoginPacketHandler
- CharacterPacketHandler
- NpcPacketHandler
- InventoryShopPacketHandler
- ItemEquipmentPacketHandler
- BattlePacketHandler
- PetPacketHandler
- PetSkillPacketHandler

Server Hello: `StoneAge Online v0.1-15`.

## Pet recovery

New protocol:

- `0x090F PetHealRequest`
- `0x0910 PetHealResponse`
- `0x0911 PetReviveRequest`
- `0x0912 PetReviveResponse`

Both requests carry one `Int64 PetId`.

Rules are server-authoritative:

- session must be `InWorld`
- pet must belong to the selected character
- Heal requires `0 < HP < MaxHP`
- Heal restores HP to MaxHP
- KO pets cannot be healed and must be revived first
- Revive requires `HP == 0`
- Revive restores `max(1, MaxHP / 2)`
- HP changes are persisted immediately to PostgreSQL

TestClient commands:

```text
petheal <petId>
petrevive <petId>
```

## Data-driven battle skill effects

`PetSkillDefinition` now supports:

```text
effect
effectPower
```

Existing offensive skills use `effect = damage`.

New skill:

```text
40004 Recovering Lick
Effect: heal_self
EffectPower: 25
```

When the pet obeys, `heal_self` restores 25% of its MaxHP and consumes the pet's action instead of dealing damage. The resulting PetHP is carried by the existing `BattleTurnResult` payload, so no protocol expansion is required.
