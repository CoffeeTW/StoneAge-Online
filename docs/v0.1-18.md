# StoneAge Online v0.1-18

## Party Follow

Party movement is now server-authoritative when the current leader moves.

Formation behavior:

1. capture the party's old positions before the leader moves
2. leader performs the normal validated `MoveRequest`
3. member 2 moves to the leader's old position
4. member 3 moves to member 2's old position
5. continue through the party roster

Rules:

- follow only starts from the current party leader
- offline members are skipped
- members on another map are skipped and are never teleported across maps
- follower destinations must still be walkable server map cells
- follower movement is emitted through normal `MoveBroadcast`
- party presence is also refreshed for each follower
- leader transfer keeps the new leader at member index 0 so formation ordering remains deterministic

This is an initial formation chain. It does not yet provide follow enable/disable, pathfinding around obstacles, catch-up teleport, or collision reservation.

## Party Battle Foundation

`BattleSession` now contains a server-authoritative participant roster:

```csharp
IReadOnlyList<BattleParticipantSnapshot> Participants
```

Each participant currently records:

- CharacterId
- IsLeader

When the party leader triggers a random encounter, `WorldPacketHandler` snapshots online party members that are on the same map and stages that roster in `BattleManager`.

`BattleManager.TryStart()` consumes the staged roster exactly once when a battle is created. If no encounter starts, the pending roster is discarded.

The current v0.1-18 battle resolution remains intentionally single-actor:

- only the leader's player stats currently act
- only the leader's active pet currently acts
- party member HP/actions/EXP/rewards are not yet resolved

This metadata is the foundation for the next version's multi-participant turn model without destabilizing the existing battle implementation.
