# StoneAge Online v0.1-14

## ClientConnection

`ClientConnection` now owns the per-client transport lifecycle:

- `TcpClient`
- `NetworkStream`
- `GameSession`
- remote endpoint information
- serialized packet sending through `ConnectionSendGate`

`TcpGameServer` creates one `ClientConnection` per accepted socket and enables `TcpClient.NoDelay`.

The packet/lifecycle interfaces expose a `ClientConnection` entry point while retaining a compatibility bridge for the existing gameplay handlers. This keeps the migration incremental without splitting connection ownership again.

## Authoritative movement response

Movement protocol is now:

- `0x0401 MoveRequest`
- `0x0402 MoveResponse`
- `0x0403 MoveBroadcast`

`MoveResponse` always returns a result code and the authoritative server position:

- `0 Success`
- `1 NotOnline`
- `2 InvalidDirection`
- `3 TooFast`
- `4 Blocked`
- `5 InvalidTarget`
- `6 DirectionMismatch`

Payload:

```text
Result Byte
MapId Int32
X Int16
Y Int16
Direction Byte
```

The server sends `MoveBroadcast` only after a successful move.

## Async TestClient receiver

The TestClient now runs one background packet receiver. Requests register a waiter for the expected response opcode before sending the request. Packets without a pending waiter are treated as unsolicited server events and printed immediately.

This removes the old manual `recv` workflow and prevents presence/movement/battle broadcasts from being consumed accidentally as command responses.

Battle actions are sent asynchronously because a battle action may result in either a turn result or an immediate battle end (escape/capture).
