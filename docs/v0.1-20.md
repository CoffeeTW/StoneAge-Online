# StoneAge Online v0.1-20

## Party battle pets

Every online same-map party participant may bring one active pet into the shared party battle.

- pet HP/ATK/DEF/AGI/elements come from the server-side database
- the first pet skill by Slot becomes the active party-battle skill
- loyalty determines whether the pet acts
- damage skills reuse the existing power and elemental calculation
- `heal_self` skills heal the pet instead of attacking
- pets participate in the same agility initiative as players and the monster
- the monster may target either a living player or a living pet

## Party battle event model

`PartyBattleTurnResult` identifies every event with explicit actor and target types:

- `0 Monster`
- `1 Player`
- `2 Pet`

Each event contains ActorType, ActorId, TargetType, TargetId, Amount, TargetHp, and IsHeal.

## Rewards

On victory:

- monster EXP is split across party participants
- surviving active pets receive the same EXP and use normal pet level progression
- one random participant is selected as drop owner when a monster drop succeeds
- PartyBattleEnd includes reward ItemId and owner CharacterId

The current inventory schema still permits only one row per CharacterId + ItemId. To avoid the known duplicate-stack unique-key failure, a party drop is skipped when the selected owner already has a full stack instead of creating a second row.

## Escape and capture

Actions remain compatible with the existing TestClient commands:

- `attack` = 1
- `defend` = 2
- `escape` = 3
- `capture` = 4

Only the party leader may use Escape or Capture.

- successful Escape ends the shared battle for every participant
- failed Escape consumes the leader action as Defend
- successful Capture creates the captured monster as a new pet owned by the party leader and ends the battle
- failed Capture consumes the leader action as Defend
- captured pets receive Bite (`40001`) in slot 0
- maximum five pets per character remains enforced

## Protocol changes

PartyBattleStart now includes optional active-pet information per participant.

PartyBattleTurnResult now carries typed player/pet/monster events and heal events.

PartyBattleEnd now contains:

- Result
- EXP per participant
- MonsterId
- RewardItemId
- RewardOwnerCharacterId
- Message

## Compatibility

Solo/Pet battle is unchanged. Party battle remains a dedicated runtime and protocol path.
